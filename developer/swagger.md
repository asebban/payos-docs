# Swagger UI Configuration

The HTTP server has built-in support for [Swagger UI](https://swagger.io/tools/swagger-ui/). When enabled, it exposes a browser-based interface for exploring and testing your OpenAPI specification, and a companion `/openapi.yaml` endpoint that serves the spec file.

---

## Prerequisites

The server serves Swagger UI from a local `swagger-ui-dist` package. This package must be installed before the server starts.

From the `payos-server-http` directory (or from your runtime directory):

```sh
npm install swagger-ui-dist
```

This creates `node_modules/swagger-ui-dist/` with the static assets (`index.html`, JS, CSS, images).

---

## Endpoints

| Endpoint | Description |
|---|---|
| `GET /swagger` | Swagger UI index page |
| `GET /swagger/` | Alias for `/swagger` |
| `GET /swagger/*` | Individual UI assets (JS, CSS, PNG, SVG) |
| `GET /openapi.yaml` | The raw OpenAPI specification file (this file is generated by `pdoc` CLI) |

---

## Configuration in `bootstrap.json`

Swagger UI is configured under the `swagger-ui` top-level key in `bootstrap.json`. All fields are optional.

```json
{
  "swagger-ui": {
    "dist-dir":     "/path/to/node_modules/swagger-ui-dist",
    "openapi-yaml": "/path/to/openapi.yaml",
    "local-only":   true
  }
}
```

### Fields

| Field | Type | Default | Description |
|---|---|---|---|
| `dist-dir` | string (path) | `<runtime>/node_modules/swagger-ui-dist` | Absolute or runtime-relative path to the unpacked `swagger-ui-dist` folder. |
| `openapi-yaml` | string (path) | `<runtime>/openapi.yaml` | Path to your OpenAPI 3.x YAML specification file, served at `GET /openapi.yaml`. |
| `local-only` | boolean | `true` | When `true`, all `/swagger` and `/openapi.yaml` requests from non-loopback addresses are rejected with `403 Forbidden`. |

Paths are resolved relative to the PayOS runtime base directory when they are not absolute. See `PayOSConfig.resolveRuntimePath()` for the exact resolution logic.

---

## Minimal setup (development)

The simplest setup relies on all defaults. Place your spec file and install the npm package alongside the runtime:

```
<runtime>/
├── bootstrap.json
├── openapi.yaml                   ← your spec
└── node_modules/
    └── swagger-ui-dist/           ← npm install swagger-ui-dist
```

`bootstrap.json` needs no `swagger-ui` key at all:

```json
{
  "servers": [
    { "protocol": "http", "host": "127.0.0.1", "port": 8080 }
  ]
}
```

Navigate to `http://localhost:8080/swagger` to open the UI.

---

## Custom paths (staging / production)

When assets or the spec file are stored outside the runtime directory:

```json
{
  "swagger-ui": {
    "dist-dir":     "/opt/payos/swagger-ui-dist",
    "openapi-yaml": "/opt/payos/specs/payments-api.yaml",
    "local-only":   false
  }
}
```

Setting `"local-only": false` is required when the UI must be reachable from a browser on a different host (e.g., a shared staging environment). See [Security considerations](#security-considerations) before doing this in production.

---

## How the UI is wired to your spec

At request time, `SwaggerUIHandler` intercepts `swagger-initializer.js` and replaces the hardcoded Petstore URL:

```js
// Original (from the npm package):
url: "https://petstore.swagger.io/v2/swagger.json"

// Patched at runtime to:
url: "/openapi.yaml"
```

This means the UI always loads your spec from the same origin, with no additional configuration inside the JS file.

## Security considerations

### `local-only` (default: `true`)

By default, every request to `/swagger` or `/swagger/*` is checked against the source IP. Requests not originating from `127.0.0.1` or `::1` receive `403 Forbidden`. This is intentional: Swagger UI exposes your full API surface and should not be publicly accessible in production.

To expose the UI to a specific set of clients while keeping it off the public internet, place a reverse proxy (nginx, HAProxy) in front and restrict access at the network layer, then set `"local-only": false`.

### Response security headers

The handler sets the following headers on every `/swagger` response:

| Header | Value |
|---|---|
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | `no-referrer` |
| `Cache-Control` | `no-store, no-cache` |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self' file:; frame-ancestors 'none'; base-uri 'self'` |

The CSP is intentionally relaxed compared to application endpoints because Swagger UI requires inline scripts and styles. These relaxed headers apply **only** to `/swagger/*` routes.

### Path traversal protection

File paths derived from the request URI are normalised via `Path.normalize()` and then verified with `toRealPath()` before any file is read. Any resolved path that escapes `dist-dir` receives `403 Forbidden`.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `503 Swagger UI not available` | `dist-dir` not found | Run `npm install swagger-ui-dist` in the runtime or set `dist-dir` to the correct path. |
| `403 Forbidden` on `/swagger` | `local-only: true` and request is not from localhost | Access from `localhost`, or set `"local-only": false`. |
| UI loads but shows Petstore spec | `swagger-initializer.js` pattern not found — file may already be patched | Check server logs for the `DEBUG` message from `SwaggerUIHandler`; if the file was pre-patched the log will say so and `/openapi.yaml` is still used. |
| `404` on `/openapi.yaml` | Spec file not found at configured or default path | Verify `openapi-yaml` in `bootstrap.json` points to an existing file. |
| Spec loads but operations fail | `local-only: true` blocks `connect-src` for remote UIs | Either access from localhost or disable `local-only` behind a secure proxy. |

---

## Configuration changes at runtime

`bootstrap.json` is watched by `ConfigWatcher` in `payos-kernel`. Changes to `swagger-ui.dist-dir`, `swagger-ui.openapi-yaml`, and `swagger-ui.local-only` take effect on the next request — no server restart is required.
